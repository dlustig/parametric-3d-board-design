## G6 Authorability (Task 18)

Each spec starts from a blank mm project (`window.__cbpd.replaceProject(newProject('mm'))`, setup only) and authors through the real UI in Chromium at a 1600 × 1200 viewport: tool buttons and keys, canvas taps on whole client pixels (so exact geometry comes from snapping, typed values or commands, never pointer precision), the drawing options bar, inspector fields, palette swatches, toolbar/inspector commands, and the Crossing tool. The hook is then only read (`getProject`, `getScene`). `compare.ts` pairs every fixture occurrence with an authored one of the same kind and material within 0.05 mm (open bands either direction; closed bands and regions from any start), requires equal widths, pairs every listed intersection through that pairing, and requires the same class and the same effective over occurrence, and equal unresolved counts. A mutation check (one root override left out of F) fails with exactly that intersection's over mismatch.

Action counts include view actions (Fit) and every field entry, tap, key and button. Elapsed time is the automated run (chromium, one worker per spec in a parallel run) and includes a deliberate 350 ms gap between canvas taps (longer than `DOUBLE_TAP_MS`, as a person's taps are); it is not a human timing.

Findings (friction, each logged by the spec as a workaround). Status after Task 22 (G6 not re-run here; Task 21 re-runs every gate): 1–3 resolved in code, 4–5 open.

1. **A line target beats a grid point that lies on it** (SPEC §7.7 priority taken literally): a tap on a grid point that is also on a Board edge/centre line or another object's bounds-edge line snaps onto the line but keeps the raw pointer coordinate along it (0.1–0.3 mm off at this zoom). B's flush second rectangle and D's diamond apexes on the Board centre line hit it. Suggested fix: when a line target wins, also snap along it to the grid (or treat line ∩ grid as point targets). **Resolved (Task 22):** `snapPoint` refines a line snap to a grid point on that line within tolerance (guide `point`).
2. **A 45° edge between grid points cannot be tapped**: angle snap captures the ray and then snaps its length to whole grid steps (85 mm for a 60√2 edge). D needed typed lengths, rotated squares, and per-point fields. **Resolved (Task 22):** with the angle captured, `snapSegmentEnd` snaps to grid points on or within tolerance of the ray (and line crossings), nearest the pointer — a 45° edge from a grid point ends on (60, 60) at 60√2.
3. **Not implemented, SPEC §7.4/§7.7**: vertex and midpoint handles on a selected Band/Region, and move snapping (selection sources to targets) — Moveable runs with `snappable={false}` and nothing replaces it. Every placement therefore went through bounds X/Y, per-point fields, or nudges. The Crossing tool also has no rail button (key `X` only), although §7.4 says the rail shows the same tools. **Resolved (Task 22):** vertex/midpoint handles with snapping and neighbour-merge delete (`e2e/vertex-handles.spec.ts`), move snapping of selection sources via `snapDelta` (`e2e/move-snap.spec.ts`), and a Crossing rail button.
4. **Rotate and Mirror only pivot on the selection's bounds centre**: F's ±90° accent instances (rotations about the lattice origin) needed a symmetric helper selection and a delete of the unwanted copy. Open.
5. **Create Motif's pivot is the painted-bounds centre**: when a fixture's definition origin is elsewhere (F: 0.499 mm off), matching its world placement needs a computed, non-round coordinate. Open.
